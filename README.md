# نيرس ليبيا — نسخة الحسابات والحجوزات

واجهة عربية متجاوبة تستكمل ملف المستودع الأصلي، ومبنية على نسخة التحديث السابقة.

## الميزات المنجزة
- استعراض الخدمات واختيار خدمة قبل تسجيل الدخول.
- إنشاء حساب وتأكيد البريد حسب إعداد Supabase، والدخول والخروج واستعادة الجلسة.
- طلب إعادة تعيين كلمة المرور وتغييرها بعد العودة من البريد.
- قراءة الاسم والهاتف من profiles دون منح أي صلاحية بناءً على user_metadata.
- إرسال طلب حجز وعرض أحدث 100 طلب للمستخدم مع حالات عربية وإنجليزية.
- منع عرض استجابة حجوزات قديمة بعد تغيير الحساب أو الخروج، وعرض البيانات كنص لمنع حقن HTML.
- رسائل أخطاء وحالات تحميل، ومنع الإرسال المتكرر أثناء الطلب.

## التشغيل
هذه صفحة ثابتة، لا تحتاج بناءً أو Node في الإنتاج:

```sh
python3 -m http.server 8080
```

افتح http://localhost:8080. يحتاج المتصفح الإنترنت لتحميل Supabase SDK المثبت عند الإصدار 2.57.4 والاتصال بالمشروع.
ارفع ملفات index.html وstyles.css وapp.js وconfig.js معًا إلى جذر الموقع. حافظ على مسار المستودع إن كنت تستخدم GitHub Pages.

## الإعداد
config.js يحتوي عنوان المشروع المطابق juxiaorwaiazfjlmkcvm ومفتاح publishable عام. لا يحتوي أسرارًا. لا تضع مفاتيح secret أو service_role في المتصفح.
لا تقرأ الصفحة الثابتة ملفات .env تلقائيًا؛ لا حاجة إلى ملف .env لهذه النسخة. عند الانتقال لأداة بناء تُعرّف آلية حقن الإعدادات ومتغيراتها عندها. .gitignore يستبعد ملفات البيئة المحلية.

في Supabase يجب التحقق من Site URL وRedirect URLs وإضافة العنوان النهائي الدقيق؛ تأكيد البريد واستعادة كلمة المرور يعودان إلى origin + pathname للموقع. لا تفترض أن إعداد localhost السابق تم تغييره.

## قاعدة البيانات الحالية
profiles وbookings موجودان وRLS مفعّلة. trigger إنشاء الملف الشخصي موجود؛ trigger حماية الدور يفرض patient على الحساب الجديد. اختيار المهنة يسجل requested_role فقط ولا يعتمد مقدم الخدمة تلقائيًا.
تم تطبيق إصلاحين على المشروع في 5 أكتوبر 2026، موثقين في docs/database-fixes.sql:
- تقييد حالة الحجز الجديد إلى pending أو قيد المراجعة مع التحقق من ملكية المستخدم.
- إصلاح recursion في سياسة تحديث المشرف عبر دالة محدودة في private تتحقق من دور المستخدم الحالي؛ لا تأخذ معرف مستخدم اختياريًا ولا تمنح أدوارًا.
الواجهة تقرأ الخدمات النشطة من services لأن trigger الحجز يرفض أي اسم خدمة غير موجود أو غير نشط.

قبل استقبال المستخدمين يلزم تأكيد Site URL وRedirect URLs وSMTP، واختبار تأكيد البريد والاستعادة وعزل حسابين في بيئة اختبار. لم تُغيّر إعدادات Auth ولم تُرسل رسائل بريد اختبارية.
