# نيرس ليبيا

واجهة عربية RTL ثابتة للحسابات وطلب الرعاية والأدلة المهنية والفرص والرسائل الخاصة ومتجر المستلزمات. هذه نسخة مستودع GitHub المطابقة لمشروع Supabase `juxiaorwaiazfjlmkcvm`؛ تختلف عن مصدر Lovable السابق.

الدفعة مكتملة في [طلب الدمج رقم 2](https://github.com/n42vvp6rsz-cell/nurse-libya/pull/2)، وتنتظر الموافقة المطلوبة لتفعيل قاعدة الإنتاج والنشر. [الموقع العامل حاليًا](https://n42vvp6rsz-cell.github.io/nurse-libya/) يعرض نسخة 5 أكتوبر؛ الصور أدناه تعرض التعديلات الجديدة ببيانات اختبار.

## الوظائف

- خدمات نشطة من قاعدة البيانات، مع اختيار الخدمة ومقدّمها قبل الدخول واستئناف الطلب بعد المصادقة.
- التسجيل والدخول واستعادة الحساب وتعديل الاسم والهاتف. نوع المهنة المطلوب لا يمنح دورًا أو صلاحية.
- حجوزات خاصة بالمستخدم، تحقق من التاريخ والهاتف والاسم، ومرجع UUID ثابت لاستعادة محاولة غامضة دون إنشاء طلب آخر. بدء طلب مختلف قرار واضح؛ إعادة تحميل الصفحة تفقد مرجع المحاولة غير المحفوظ محليًا، لذا راجع حجوزاتك قبل إعادة الإرسال.
- أدلة الأطباء والتمريض والمؤسسات مع بحث وفلاتر المدن؛ إسقاطات عامة محدودة دون بيانات المرضى أو هواتف الحسابات الخاصة.
- وظائف نشطة غير منتهية، تقديم وسحب ومتابعة الطلبات الخاصة.
- دورات منشورة بعد الموافقة، وطلبات التحاق مجانية قيد المراجعة. لا تحصيل دفع أو تأكيد قبول تلقائي.
- طلبات اعتماد المهنة، وإدارة المؤسسات الخاصة بالحساب، ونشر وظائف ودورات للحسابات ذات الدور المخوّل في قاعدة البيانات.
- إنشاء وتعديل ملف مقدّم الخدمة في الدليل، ومراجعة الإدارة للطلبات والمؤسسات والدورات والملفات والحجوزات.
- رسائل خاصة بين أطراف مخوّلة: اختيار مقدّم خدمة من الدليل، صندوق وارد، إرسال واستعادة المحاولة نفسها، وتعليم الرسالة كمقروءة لدى مستلمها.
- متجر مستلزمات طبية وتمريضية: بحث وسلة وطلب بالدفع عند الاستلام، أسعار بالدينار الليبي بثلاث منازل عشرية، متابعة الطلبات الخاصة وإدارة المنتجات والمخزون والطلبات للمشرف المخوّل.
- حجز المخزون والأسعار المحفوظة وإلغاء الطلب واستعادة المخزون معاملات ذرية في قاعدة البيانات. لا توجد منتجات أو أسعار تجريبية في الإنتاج؛ يضيف المشرف المنتجات الفعلية بعد التفعيل.
- فصل الحسابات، ومنع الردود المتأخرة والإرسال المتزامن، وعرض محتوى المستخدم كنص.

## التشغيل

لا تحتاج ملفات الإنتاج بناءً أو Node:

```sh
python3 -m http.server 8080
```

افتح `http://localhost:8080`. انشر `index.html` و`styles.css` و`config.js` وملفات JavaScript الموجودة في الجذر معًا. تعتمد المصادقة على Supabase SDK المثبت عند الإصدار `2.57.4`؛ خط Tajawal له بديل محلي عند تعذر تحميله. حافظ على المسار الأساسي إذا استُخدم GitHub Pages.

`config.js` يحتوي إعداد Supabase العام الموجود أصلًا في المستودع. لا تضع مفاتيح secret أو service_role في المتصفح، ولا تحتاج هذه الصفحة ملفات `.env`.

## قاعدة البيانات وحالة التفعيل

اقرأ [خطة التفعيل والنشر](docs/deployment-oct7.md) و[العقد الحالي](docs/current-database-contract.md). ملفات SQL الثلاثة للمشروع المطابق **لم تُطبّق**. رفضت المراجعة الآلية تفعيل إصلاح الإنتاج لأن تغييرات الجداول والسياسات والصلاحيات والوظائف الدائمة تحتاج موافقة مستخدم صريحة؛ الاختبارات المحلية لا تمنح هذا التفويض.

ترتيب التفعيل بعد الموافقة هو [الإصلاح الأساسي](docs/proposed-database-fixes.sql)، ثم [عقد الرسائل](docs/messages-database-fixes.sql)، ثم [عقد المتجر](docs/store-database.sql). يتضمن الأساسي حماية توثيق الملفات ونشر الدورات، وإصلاح اعتماد الحساب، ومراجعة الحجز والطلب المرتبط ذريًا، ومنع المشاركين من تغيير حالة أو هوية الطلب المرتبط مباشرةً.

تحمي RPCs القراءة `nurse_app_contract_version()` و`nurse_messages_contract_version()` و`nurse_store_contract_version()` عمليات الكتابة الحساسة. غياب العقد أو اختلاف الإصدار يمنع تلك العمليات، بما فيها الإرسال والشراء والإدارة، دون الرجوع إلى كتابات خام غير آمنة. لا تُفعّلها بتغيير JavaScript أو بإعداد محلي. العمليات القائمة، مثل حفظ بيانات الحساب والحجز وطلب الاعتماد، تستعمل العقد الحالي.

بعد التفعيل، تُراجع سياسات RLS والصلاحيات وعلامات الإصدار من بيانات الكتالوج، ثم يُدمج طلب الدمج للنشر على GitHub Pages. إعدادات Auth Site URL وRedirect URLs وSMTP وتسليم البريد لم تُختبر حيًا. `docs/database-fixes.sql` سجل الإصلاحات السابقة في 5 أكتوبر، ولا يُعاد تشغيله تلقائيًا.

تحتاج علامات التوثيق التاريخية إلى مراجعة بشرية؛ كانت قابلة للتعديل من أصحاب الملفات قبل الإصلاح. الطلبات القديمة غير المرتبطة بحجز تحتفظ بسياساتها السابقة، ولا توفر هذه النسخة محررًا عامًا لها. الرسائل القديمة تظل قابلة للقراءة لأطرافها، لكنها لا تمنح بمفردها صلاحية الرد الجديدة لأن هوية مرسلها كانت قابلة للتعديل. لا ينشئ التعديل مشرفًا ولا يغيّر دور مستخدم بعينه.

## الاختبارات

التطوير والاختبارات على Node 24 أو أحدث:

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run test:browser
npm run test:db
```

نجحت **130 حالة اختبار وحدات** و**21 سيناريو Chromium** و**85 سيناريو قاعدة بيانات** على PostgreSQL 17.5 عبر PGlite المثبت عند `0.3.16`. التفاصيل في [تقرير التحقق النهائي](docs/validation-continuation-oct7.md) و[نتائج الإصلاح الأساسي](docs/database-runtime-results.md) و[عقد الرسائل](docs/messages-contract.md) و[عقد المتجر](docs/store-contract.md).

اختبارات DOM تستخدم Supabase محاكى. فحص المتصفح يحتاج Chromium أو `CHROMIUM_BIN`، ويحجب الاتصالات الخارجية ويستبدل SDK والإعدادات قبل تحميل الصفحة. اختبارات SQL تنفّذ المعاملات والصلاحيات وRLS فعلًا على سجلات محلية مصطنعة؛ محرك الجلسة الواحدة لا يثبت سلوك اتصالات إنتاج متزامنة أو PostgREST أو JWT أو تسليم البريد. لم تُقرأ بيانات المرضى ولم تُنشأ حسابات أو حجوزات أو رسائل أو طلبات شراء حقيقية.

المتجر يبدأ بالدفع عند الاستلام. الدفع الإلكتروني يحتاج اختيار مزوّد وحساب تجاري قبل تطوير عقده. المحتوى التدريبي التفصيلي يحتاج مواد فعلية. اتصال Lovable ما زال مفصولًا؛ نشر هذه الدفعة سيكون عبر مستودع GitHub وGitHub Pages الموجودين.
